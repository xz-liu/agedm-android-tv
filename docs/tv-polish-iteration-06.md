# 0.3.3：修复 HLS 下载清单与本地分片不一致

用户在 0.3.2 提供的电视照片仍显示《GATE 奇幻自卫队》第 01 集“已下载”，但本地播放报 `ERROR_CODE_IO_UNSPECIFIED`。上一轮数据源级测试不足以验证完整下载到离线播放流程。

## 复现证据

连续两次请求 GATE 第一季首集的重定向后清单，响应都是 84,794 字节，但内容及首个分片地址不同。地址携带每次生成的参数；不能靠删除查询参数合并缓存键，否则会破坏签名和资源身份。

检查项目固定的 [Media3 1.4.1 HlsDownloader](https://github.com/androidx/media/blob/1.4.1/libraries/exoplayer_hls/src/main/java/androidx/media3/exoplayer/hls/offline/HlsDownloader.java)：对于直接媒体清单，先在原 URI 缓存清单 A，又在 `manifest.baseUri`（HTTP 重定向后的 URI）重新读取清单 B，实际下载 B 中的分片。播放器从原 URI 读取 A，使用只读缓存时找不到 A 中的分片。

新增 MockWebServer 回归测试模拟相同重定向及每次变化的分片参数。原下载器成功结束下载后，A 中的分片确实未缓存，B 中的分片完整；原离线轨道准备失败。测试使用自生成的黑屏/正弦音 TS，不保存用户视频或公开 CDN 签名。

## 修改

- HLS 下载直接沿用首次缓存的媒体清单；主清单仍按所选轨道加载子清单。底层仍由 Media3 SegmentDownloader 管理缓存、重试、取消、并发和字节范围。
- 旧任务播放时读取持久化的重定向元数据。只有第二份媒体清单及其所有分片、初始化段、加密密钥都完整存在于缓存时，才选择它作为播放入口。没有网络补读、删除或重新下载。
- 旧任务中途升级后继续下载时，若第二份清单不完整，则使用新下载器补齐的原清单，不误选不完整缓存。
- 删除旧下载时同时清除第二份清单及其分片，避免遗留占用空间。
- 播放异常日志保存完整异常链，以便后续区分实际缓存、解析和解码错误。
- 播放器、剧集身份、观看记录、遥控器交互和下载界面不变。

## 验证

新增 5 项集成测试：稳定重定向、动态分片参数、旧下载迁移、旧任务中断后续传，以及多清晰度选轨/AES 密钥/初始化段/字节范围。前四项执行下载、关闭并重新打开缓存、关停 HTTP 服务、离线准备音视频轨道，并确认删除后缓存占用归零。

全部 48 项测试、`lintDebug`、`assembleDebug`、`assembleRelease` 通过。Release 安装包为 0.3.3 / versionCode 8，签名证书与 0.3.2 一致，可以覆盖安装保留应用数据。

以上验证覆盖 Media3 下载及本地解封装，不等同于用户电视的硬件解码实测。缺失文件或旧版只保存清单的下载不能凭此修复；已有完整第二份快照的下载可直接复用。没有连接用户电视，不能仅凭截图断言不存在其他故障。
